# 产品与实现边界

## 产品原则

1. **服务于“手机截图立刻在 Mac 使用”**，不是云相册或通用文件同步系统。
2. 一次配对、一次设置，日常一次触发；不要每次询问画质或路径。
3. 附近能直传就不绕公网；没有服务器仍然可用。
4. 成功要有接收端保存依据。未知和失败保持可见，不牺牲一致性换一个“成功”提示。
5. 私密配置与代码分离，独立 iOS App 不依赖私人容器。

## 模块

| 模块 | 职责 |
| --- | --- |
| `Sources/PhoneSnap` | 菜单栏生命周期，Mac 截图／编辑／钉图，接收与落盘，配对 UI |
| `Sources/NearbyTransport` | 附近发现、TLS-PSK 连接、传输帧、回执、加密中转、画质准备、诊断 |
| `ios/PhoneSnap` | SwiftUI 配对与测试入口，PhotosPicker，两个 AppIntent；直接编译共享源码 |
| `relay/server.mjs` | 鉴权、短时内存暂存密文、转发和回执转交；无图片解密能力 |

iOS 工程不复制传输实现；除 Mac 专用回执落盘逻辑外，使用根目录的同一组 Swift 源文件。

## 自动选路

`AutomaticTransfer` 只在直传返回“未开始、不可用”时调用中转。直传抛错不会触发另一通路的重发。发送编号用于关联，但不独立证明送达。

附近连接使用 `_phonesnap._tcp` Bonjour 服务和配对预共享密钥。启用点对点发现不意味着每台设备、每种热点或所有后台状态均可建连。附近帧最大 32 MiB。

中转只接受配置好的 HTTPS 根域名，不带账号、查询串或路径。每个通道独立上传／接收凭据；图片与回执使用不同方向派生的加密密钥。图片原始明文上限为 8 MiB，中转 wire 有单独限制，客户端超过限制会报错而非切换明文。

服务器支持二进制密文与旧 JSON 协议；新客户端默认二进制。服务器内部可能做表示转换，但新链路不会把 Base64 膨胀放到图片传输线上。回执体积很小，仍可使用 JSON。

服务器不充当离线网盘。Mac 需要在线轮询，密文仅在有限等待窗口内保留于内存；重启会丢弃进行中的传输。不要把它用于可靠离线队列或大量并发设备。

## 计时与界面

- “接收时间”是墙钟时间，“接收耗时”是 Mac 本机阶段计时。
- 手机全程耗时从 AppIntent / App 操作开始，不含之前的系统截图动作。
- 服务器等待指标包含保存回执链路，不能全部归因于中转性能。
- 保存文件大小、网络包大小、像素尺寸分开显示，历史缺字段不补猜测。

## 兼容能力

上游 USB 相册导入和旧 HTTP 快捷指令接收保持为独立入口，不混入自动加密选路。HTTP 入口只允许可信局域网内的显式使用，安全性不同，详见 [安全说明](../SECURITY.md)。

## 验收边界

协议单元测试、跨语言互通、本机编译、独立 iOS 真机配对与真实网络测试是不同层次。原模块曾有实机直传／中转反馈，不代表独立 App 在所有设备与系统版本上已通过验收。

当前发布优先保证代码可读、可构建、默认无私人配置。独立 App 的端到端真机回归、稳定签名分发、更多网络矩阵仍需实测；不为这些未完成项预先承诺时间或性能。
