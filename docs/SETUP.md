# 构建、配对与一次触发

## 1. Mac 接收端

安装 Xcode 26+ 并完成首次启动配置；测试还需要 Node.js 22+。在仓库根目录运行：

```sh
PHONESNAP_ALLOW_ADHOC=1 PHONESNAP_APP_PATH=dist/PhoneSnap.app bash scripts/build-app.sh
```

产出 `dist/PhoneSnap.app`，只做临时签名，不自动安装或启动。已有同名输出时脚本会停止，避免覆盖。

正常退出旧版本后，把你选择的构建放在固定应用目录，再启动它。不要同时运行多个副本。长期使用建议设置 `PHONESNAP_SIGN_IDENTITY` 为你自己的稳定代码签名身份，不要把证书或私钥交给项目维护者。签名连续性不保证系统不会再次询问权限。

从菜单栏打开“设置 iPhone 附近传输…”，开启附近接收。Mac 自身截图才需要屏幕录制权限；按 App 中的指引授权当前实际运行的副本。不要例行清空 TCC 或钥匙串。

## 2. 独立 iPhone App

用 Xcode 打开 `ios/PhoneSnap.xcodeproj`。选择 `PhoneSnap` target，在 Signing & Capabilities 中选择你自己的 Team，把 Bundle Identifier 改成你拥有的唯一标识，再选择设备构建运行。iOS 最低版本为 26。

仓库没有 Apple 账号、开发者 Team ID、签名证书、描述文件或安装服务。系统的设备信任、开发者模式和签名有效期由你自己的开发环境管理，不要为了安装关闭 Mac 的系统安全保护。

只验证编译、不签名或安装时可运行：

```sh
xcodebuild -project ios/PhoneSnap.xcodeproj -scheme PhoneSnap -configuration Release \
  -sdk iphoneos -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO build
```

独立 App 不会覆盖其他私人 App，也不会自动迁移其钥匙串与快捷指令。首次安装请为它单独配对。

## 3. 附近配对

1. 在 **Mac PhoneSnap → 设置 iPhone 附近传输…** 中导出 `.phonesnappair` 文件。
2. 通过你信任的私密渠道交给自己的 iPhone；文件含配对秘密，不要放公共网盘或 GitHub。
3. 在 **iPhone PhoneSnap → 管理与帮助 → 附近配对管理** 导入。核对来自自己的 Mac 后确认。
4. 允许 iOS 的本地网络访问，两端开启 Wi-Fi，Mac 保持唤醒。先同一局域网测试，不要求自动切换网络。
5. 点击“选择图片 · 自动发送”，使用无隐私测试图片。以 **Mac 实际收图 + 手机保存确认** 作为验收；“已配对”不是连接成功。

连接热点或附近点对点发现受网络和系统条件影响，不能仅凭“开着 Wi-Fi”认定可用。防火墙、VPN、访客网络隔离、Mac 休眠都是需要分别检查的因素。

## 4. 配置一次触发

在 **iPhone 快捷指令 App** 新建快捷指令：

1. 添加系统“截屏”动作。
2. 添加 PhoneSnap 的“发送图片到 Mac（自动选路）”。
3. 把上一步的截屏结果作为“图片”输入。
4. 手动运行一次，完成系统必要提示并核对收图；再按个人习惯绑定操作按钮或轻点背面。

“发送图片到附近 Mac”只走直传，不能测试公网兜底。普通侧边键截图不会自动运行上述快捷指令；系统动画与授权提示也不会被 App 移除。

## 5. 公网兜底（可选）

没有服务器也能附近直传。需要跨网络时，按 [中转部署](../relay/README.md) 配置**自己的** HTTPS 域名。附近配对与中转配对相互独立，不需要删除前者。

手机中选择“原图”或“快速”后会记住设置，仅影响公网路径。快速模式保持像素尺寸，但有损编码可能影响小字；透明、多帧、小图或无压缩收益的输入保留原图。Mac 保存后的 PNG 大小不能当作网络上传大小。

## 故障定位

- 先看两端最近一次诊断和 Mac 最近截图，再决定是否重发；回执丢失时 Mac 可能已经保存。
- 诊断显示 UTC 与北京时间。各设备单调时钟不能跨设备相减；Mac 空闲等图的长轮询时间不是传输耗时。
- 缺失的网络指标不按零填，Wi-Fi 接口不自动等于“同 Wi-Fi”或“热点”。
- 只用无隐私图片复现。提交 Issue 前删掉日志中的个人路径、地址与标识，不附配对文件。
- 更新后若图标显示未立即变化，不要为了图标删除配对或卸载 App；检查正在运行的版本。重启后的恢复不等于已确认根因。
