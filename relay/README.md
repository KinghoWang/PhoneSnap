# 可选自建加密中转

附近直传不需要服务器。仅当手机与 Mac 无法直连、且你愿意维护服务器时部署本组件。

需要一台可运行 Node.js 22+ 或 Docker 的主机、自己的域名、有效 HTTPS 证书与合适的网络带宽。本仓库不提供默认公共服务器。不要把部署成功理解为手机到 Mac 的全流程验收。

## 1. 生成两份不同文件

在 **Mac PhoneSnap → 设置端到端加密中转… → 创建独立加密配对** 中输入自己的 HTTPS 根域名，例如 `https://snap.example.com`。不支持带路径、账号、查询参数或非 443 端口的地址。

再分别导出：

- **手机私密配对** `.phonesnaprelay`：含解密密钥，只交给自己的 iPhone，在公网配对管理中导入。
- **服务器配置** `phonesnap-relay-channels.json`：不含图片密钥，但含访问凭据，只上传到你自己的服务器。

不要从服务器分发手机配对文件，不要将任何一份加入 Git。已有配对时界面不会悄悄覆盖它。

## 2. 启动服务

把服务器配置放到本目录 `private/channels.json`。该文件不随仓库提供：服务在缺少配置时会停止，不使用内置测试凭据。

### Docker Compose

准备文件时限制读取权限；容器以 `65532:65532` 运行，所以它必须能读取挂载文件。在 Linux 服务器上，可仅对这份配置设置 owner / mode，别批量修改其他目录：

```sh
sudo chown 65532:65532 private/channels.json
sudo chmod 600 private/channels.json
docker compose up -d --build
curl --fail http://127.0.0.1:8787/healthz
```

预期健康响应为 `{"relay":"e2ee-v1"}`。端口仅绑定本机环回；不要改成公网暴露的 `0.0.0.0:8787` 映射。容器内部监听 `0.0.0.0` 以接收 Docker 映射，这与宿主机公开监听不是一回事。

### 不使用 Docker

让一个非 root 服务账号以只读方式访问配置，并用你的进程管理器管理生命周期。前台验证示例：

```sh
PHONESNAP_RELAY_CONFIG="$PWD/private/channels.json" node server.mjs
```

默认只监听 `127.0.0.1:8787`。不要为了启动问题将配置权限放宽给所有人。

## 3. 反向代理 HTTPS

以下是 Caddy 的**独立站点片段**。替换为自己的域名，仅加入自己的现有配置，不覆盖别的站点。修改前备份，配置校验成功后再 reload：

```caddyfile
snap.example.com {
    request_body {
        max_size 12MB
    }
    reverse_proxy 127.0.0.1:8787
}
```

DNS 指向你的服务器；按需开放 HTTPS，证书签发所需端口由你的证书方案决定。不要公开中转配置目录，不记录认证头和请求体。反代缓冲、上传速率和服务器出口带宽都会影响大图速度。

## 4. 端到端验收

1. Mac 开启“加密接收”，App 保持运行且 Mac 不休眠。
2. iPhone 导入的是手机配对文件，选择一张无隐私图片，从“手动公网发送与画质”发送。
3. 确认 Mac 实际保存、手机显示可验证的保存成功。`/healthz` 成功不能代替这一步。
4. 再测试自动兜底：暂停 Mac 的附近接收，保留中转接收；使用自动选路动作，确认选择中转且保存成功。
5. 测试结束恢复附近接收。不要删除配对、停止 Mac App 或修改其他服务来制造兜底条件。

## 容量、日志与升级

- 原始明文上限 8 MiB；二进制封装和旧 JSON 请求有单独上限。公网快速模式可降低图片大小，但不保证任意图片都压缩。
- 服务器仅做短时内存转发，不是离线网盘；Mac 离线、超时或重启可能中断传输。
- 每通道并发受限，整个服务连接数有上限。大规模多用户部署不在当前验收范围。
- Docker 例子限制 256 MiB 内存、64 个进程、2 个 1 MiB 日志文件，并关闭 core dump。
- 日志只用于阶段诊断。分享前仍需审阅并脱敏；不要把诊断编号误当作独立送达证明。
- 升级前保留旧镜像和配置；新容器完成本机健康检查和实际发送后再验收。不要同时让两个实例抢占同一个端口。

协议与保密限制见 [SECURITY](../SECURITY.md)；测试执行 `node --test server.test.mjs`。
